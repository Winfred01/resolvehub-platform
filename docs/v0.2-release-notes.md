# ResolveHub v0.2 Release Notes

Current roadmap mode: `ANALYTICS_ASSISTED_V0_2`.

ResolveHub v0.2 builds on the completed Portfolio-first v0.1 baseline with
deterministic, explainable, advisory analytics-assisted triage. The v0.2 core
path has merged Issue #23, Issue #24, Issue #25, and the analytics-specific
quality/security/E2E gates through PR #59.

## Included

- FastAPI category and priority suggestions with deterministic scoring,
  confidence, explanation, low-confidence fallback, and advisory semantics.
- FastAPI duplicate ticket suggestions with ranked candidate IDs, matching
  signals, confidence, explanation, self-ticket exclusion, and candidate caps.
- Backend suggestion retrieval and explicit review recording endpoints for
  visible tickets, including the `analyticsAvailable` fallback flag.
- Frontend suggestion display, loading, failure, accept, ignore, and override
  states in the ticket workflow.
- Audit-only analytics review activity using `ANALYTICS_SUGGESTION_REVIEWED`
  and safe field names such as
  `analyticsSuggestionReview`, `suggestionType`, `decision`, `categoryId`,
  `priority`, and `duplicateTicketId`.
- Analytics-specific quality gates for malformed responses, timeout fallback,
  whitespace/minimal input, candidate limits, advisory E2E review, and unsafe
  logging checks.
- Local demo packaging with fictional category, priority, duplicate, and
  analytics-unavailable scenarios.

## Local Demo

Start:

```bash
docker compose up --build
```

Verify:

```bash
curl http://localhost:5173
curl http://localhost:18080/api/health
curl http://localhost:8000/analytics/health
```

Reset:

```bash
docker compose down --volumes
docker compose up --build
```

PostgreSQL is published on `localhost:15432` by default to avoid common local
port conflicts; set `POSTGRES_PORT` when a different host port is needed.

## Analytics Demo Script

1. Open the ticket workspace.
2. Create or inspect a fictional support ticket with a clear triage signal.
3. Show the advisory category and priority recommendation with confidence and
   explanation.
4. Accept a category or priority recommendation and confirm the value is staged
   for normal ticket update, not applied as hidden ticket truth.
5. Review duplicate candidates and record an explicit duplicate review decision.
6. Show low-confidence or analytics-unavailable fallback, confirming the ticket
   workflow remains usable.
7. Review activity history evidence that only safe field names were recorded.

## API Examples

Read advisory suggestions:

```bash
curl http://localhost:18080/api/tickets/<ticket-id>/analytics-suggestions \
  -H "Authorization: Bearer <token-from-login>"
```

Record a triage review:

```bash
curl -X POST http://localhost:18080/api/tickets/<ticket-id>/analytics-suggestions/reviews \
  -H "Authorization: Bearer <token-from-login>" \
  -H "Content-Type: application/json" \
  -d '{"suggestionType":"TRIAGE","decision":"ACCEPT","categoryId":"network","priority":"HIGH"}'
```

Request analytics service triage directly in local development:

```bash
curl -X POST http://localhost:8000/analytics/suggestions/triage \
  -H "Content-Type: application/json" \
  -d '{"title":"VPN access blocked","description":"Fictional support queue cannot connect."}'
```

Request duplicate suggestions directly in local development:

```bash
curl -X POST http://localhost:8000/analytics/suggestions/duplicates \
  -H "Content-Type: application/json" \
  -d '{"ticket":{"id":"RH-DEMO-2001","title":"VPN access blocked","category":"network","priority":"HIGH"},"candidates":[{"id":"RH-DEMO-2002","title":"VPN queue access blocked","category":"network","priority":"HIGH"}]}'
```

## Privacy And Failure Modes

Analytics suggestions are deterministic and advisory. They do not call external
AI providers, train opaque models, automatically mutate ticket category,
priority, status, assignment, closure, or duplicate state, or merge duplicate
tickets. Ticket changes still require the existing explicit ticket update
workflow.

Analytics request and demo data must stay fictional. Do not commit real
customer data, employer data, Gmail content, job-search data, browser session
data, private addresses, phone numbers, credentials, tokens, cookies, or
production secrets.

If analytics is unavailable, malformed, slow, or low confidence, the backend
returns safe advisory fallback values and the frontend keeps the ticket workflow
usable.
