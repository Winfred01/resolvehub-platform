# ResolveHub v0.1 Release Notes

Current roadmap mode: `PORTFOLIO_FIRST_V0_1`.

Portfolio-first v0.1 is complete on `origin/main`. Issue #27 prepared the
portfolio-ready local demo and release package for the implemented v0.1 scope
and was merged through PR #52.

## Included

- React and TypeScript frontend shell, ticket workspace, Kanban workflow, and
  dashboard UI.
- Spring Boot backend for authentication, role authorization, ticket lifecycle,
  search/filter, assignment, comments, activity history, and dashboard APIs.
- FastAPI analytics service health scaffold.
- Docker Compose local topology for frontend, backend, analytics, and
  PostgreSQL.
- Issue #26 quality gates covering CI validation, Playwright smoke tests,
  accessibility-oriented frontend coverage, backend authorization regressions,
  and privacy checks.
- Issue #27 demo package with fictional seed manifest, reset instructions,
  health-check verification, and portfolio demo script.

## Local Demo

Start:

```bash
docker compose up --build
```

Verify:

```bash
curl http://localhost:5173
curl http://localhost:18080/api/health
curl http://localhost:8000/analytics/health
```

Reset:

```bash
docker compose down --volumes
docker compose up --build
```

PostgreSQL is published on `localhost:15432` by default to avoid common local
port conflicts; set `POSTGRES_PORT` when a different host port is needed.

## Demo Data

Demo personas, tickets, categories, and dashboard expectations are defined in
`tests/demo-seed-data.json`. All entries are fictional. Demo credentials are
generated at reset time and are not committed.

## Deferred Scope

- #23 category and priority suggestions remain optional stretch for v0.1.
- #24 duplicate ticket suggestion is deferred to v0.2.
- #25 full analytics workflow integration is deferred to v0.2.

The v0.1 release should not claim production analytics, public production
deployment, or production-grade PostgreSQL operations.

## Validation

Run:

```bash
node scripts/validate-demo-release.js
node scripts/validate-quality-gates.js
docker compose -f docker-compose.yml config
```

Use the broader Issue #26 validation suite before final human review when
release confidence needs a full refresh.
